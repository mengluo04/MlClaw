# Cron 定时任务

定时任务由 MlClaw 服务端执行。网页关闭不影响调度，服务器关机、服务退出或电脑休眠时无法执行；恢复后不补跑错过的触发。结果保存在网页，可按计划设置投递到已绑定的 QQ 或微信，不发送浏览器系统通知。

## 使用步骤

1. 登录后进入“定时任务”，填写计划名称、类型、Cron 表达式及内容。
2. 点击“预览执行时间”，核对服务器时区和未来 5 次执行时间。
3. 保存并启用计划。新计划从保存后的下一次匹配时间开始。
4. 查看“执行记录与提醒”。固定提醒可标为已读；AI 任务点击“打开结果会话”查看消息、工具和用量。

固定提醒不调用模型；只读 AI 任务使用实际创建任务时的全局默认模型、助手配置和显式记忆，可能产生模型调用费用。AI 每次新建独立会话，不承接上一次运行的聊天历史。最多保存 100 个未删除计划。

只读 AI 任务默认允许文件工具 `list_directory`、`read_text`、`search_text`，继续受工作目录路径和大小边界约束；另可使用只读 `search_memories`、`search_tasks`、`read_task`，范围与预算见 [摘要与检索说明](CONTEXT_MEMORY.md)。在“联网搜索”设置中保存有效密钥、启用联网并单独允许定时任务联网后，新任务还可使用 `web_search`；正文读取另受 `allowFetch` 开关控制。另可根据任务自主使用 `search_skills`、`read_skill`、`read_skill_resource` 加载技能说明，不能借技能改变只读权限，详见 [技能说明](SKILLS.md)。写文件（包括新建）、命令执行均被服务端拒绝。提示词无法提升权限。联网配置、预算及撤销语义见 [联网搜索说明](WEB_SEARCH.md)。

## Cron 与服务器时区

规则只接受五段数字 Cron：`分 时 日 月 周`，支持 `*`、逗号、范围 `-`、步长 `/`。不接受秒字段、`@daily` 等别名、英文月份/星期、随机 `H` 或 `L/#` 等扩展。

| 表达式 | 含义 |
| --- | --- |
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1-5` | 周一至周五 09:00 |
| `*/30 * * * *` | 每小时的 00、30 分钟 |
| `0 18 * * 0` | 每周日 18:00 |
| `0 9 1 * *` | 每月 1 日 09:00 |

星期 0 和 7 都表示周日。“日”和“周”同时限制时采用标准 Cron 的或关系，例如 `0 9 1 * 1` 表示每月 1 日或每周一的 09:00。表达式解析和下一次时间计算使用 [cron-parser](https://github.com/harrisiirak/cron-parser)，页面预览与后台使用相同模块。

服务启动时读取服务器进程的系统时区，所有计划统一使用该时区，不使用浏览器时区或助手配置中的时区。修改服务器时区后重启服务，新触发时间重新计算；历史执行保留当时的时区快照。业务时间存储及接口统一为服务器系统本地时间 `YYYY-MM-DD HH:mm:ss`，页面直接显示，历史记录保留保存时的本地时间；历史快照的时区仅表示当次计划解释 Cron 的时区。

扫描周期为 2 秒，属于分钟级调度，不承诺精确到秒。服务卡顿或休眠导致触发迟到满 1 分钟时，跳过截至当前时间的积压，保留一条区间汇总记录，不逐条补建多天记录。时区中的夏令时行为由解析库处理，没有单独的用户配置。

## 执行与操作语义

| 情况或操作 | 行为 |
| --- | --- |
| 网页/渠道任务占用执行名额 | AI 等待，按应执行时间最多等 10 分钟；不抢占当前任务 |
| 同计划有待执行或运行中的实例 | 新 Cron 触发记录为跳过；新的手动运行返回冲突 |
| 固定提醒到期 | 直接持久化，不占模型任务名额 |
| 暂停、编辑 | 取消未启动实例，运行中的实例保持快照；启用时从保存后的下一次 Cron 时间开始 |
| 删除 | 软删除计划并取消未启动实例；历史、已读状态、结果会话和运行中的实例保留 |
| 批量启用、禁用、删除 | 先校验所选计划的归属和版本，再在同一事务中执行；任一项冲突时全部不修改 |
| 立即运行 | 可以用于已暂停计划；不改变下一次 Cron 时间；相同请求键返回原执行 |
| 取消本次执行 | 待执行记录直接取消，运行中通过现有任务取消机制中止；不暂停计划 |
| 模型未配置、调用失败或超时 | 本次失败，不自动重试；后续正常 Cron 触发仍可执行 |
| 服务重启 | 已启动任务标为中断或保留已落库终态；未启动实例取消；停机错过触发记录汇总后跳过 |
| 删除结果会话 | 执行历史与终态保留，结果链接清空；原幂等请求不重新创建任务 |

运行记录每页 50 条，可筛选计划、未读提醒和加载更早记录。已读状态持久化，刷新或重新登录后保留。页面每 5 秒刷新记录；打开结果会话后复用现有任务 SSE。历史记录尚无自动过期清理，长期高频使用会增加数据库体积。

## QQ／微信结果投递

新建或编辑计划时选择“投递渠道”：默认仅站内，也可选择已启用、已完成 `/bind` 本人绑定的 QQ 或微信，无需另填接收人。保存后固定提醒或成功的 AI 任务会投递文本，站内内容和结果会话仍保留。

发送状态在“执行记录与提醒”中独立显示：等待投递、发送中、平台已确认发送、发送失败、发送结果未确认或未投递。任务完成不等于发送成功；平台确认也不代表本人已读。

- QQ 使用主动消息请求，不复用旧消息 ID；需要平台允许该机器人发送主动消息。
- 微信使用已绑定本人的最近入站 `context_token`。缺少上下文时明确失败；若平台拒绝，可先发一条消息给机器人，再手动运行计划。
- 渠道只发送固定提醒正文或 AI 生成结果，不添加计划名称和触发时间；名称、时间保留在网页执行记录中。每次只发送一条最多 1400 字符的文本；超长结果标注截断，完整结果在网页查看。失败、取消、跳过的执行不投递正文。
- 渠道暂未连通最多等待 10 分钟，之后标为失败；发送失败或结果未知不自动重试，也不重新调用模型。手动运行会创建新的执行及新的投递。
- 解除绑定会撤销旧快照，即使重新绑定同一人也需编辑计划重新保存渠道；停用或移除后不发送，不自动切换账号。
- 重启不补发旧结果：待发送取消，发送中标为未知，成功后尚未登记投递的空档也取消。暂停计划取消未开始执行，已完成结果的投递不因此撤回。
