# MlClaw

**部署在自己服务器上的个人 AI 助手。**

通过网页、QQ、微信、Telegram、Slack、Discord、钉钉或飞书与助手对话，让它帮你搜索资料、整理文件、运行脚本，或按计划完成重复任务。聊天记录、应用配置和工作区文件保存在你的部署环境中；模型推理、联网搜索及消息投递按配置调用相应服务。

MlClaw 面向单用户使用，采用 TypeScript、Fastify、Vue 3 和 SQLite，无需单独安装数据库服务。

## 功能一览

| 功能       | 可以做什么                                                                             |
| ---------- | -------------------------------------------------------------------------------------- |
| 多模型对话 | 配置多个提供商和模型，设置全局默认模型，也可在网页对话中临时切换模型                   |
| 流式聊天   | 实时查看回复，停止生成，查看工具执行过程与历史会话                                     |
| 联网搜索   | 接入 Tavily、Firecrawl、Exa、Brave Search 或 SearXNG，查找资料并读取支持提取的网页正文 |
| 文件与脚本 | 浏览、上传、下载、整理工作区文件，让助手创建和运行脚本                                 |
| 长期记忆   | 手动维护个人偏好和常用背景信息，供后续任务使用                                         |
| 会话摘要   | 手动生成摘要，或在模型报告上下文超限后自动压缩并继续对话                               |
| 技能管理   | 从工作区读取 `SKILL.md` 技能包，按任务需要加载说明和配套文件                           |
| 定时任务   | 创建只读 AI 任务或脚本任务，支持 Cron、启停、立即运行、取消和执行记录                  |
| 消息渠道   | 支持七类机器人私聊，定时结果可推送到机器人、WeCom Bot、邮箱和 Webhook               |
| 个性化设置 | 配置助手名称、角色、行为规则、头像，以及网站名称和图标                                 |
| 运行记录   | 查看任务结果、工具调用、耗时、服务上报用量和系统日志                                   |

模型接口目前支持 **OpenAI Chat Completions 兼容协议**。工具调用、搜索和渠道收发的实际效果取决于所选模型、服务配置及平台权限。

## 快速开始

先获取代码：

```sh
git clone https://github.com/mengluo04/MlClaw.git
cd MlClaw
```

可选择 Docker 或 Node.js 启动。模型密钥、助手和渠道配置均在网页完成，无需创建 `.env`。

### 方式一：Docker

安装好 Docker 后，在项目根目录构建并启动：

```sh
docker build -t mlclaw:local .
docker run -d --name mlclaw --restart unless-stopped -p 3000:3000 -e TZ=Asia/Shanghai -v mlclaw-data:/app/data -v mlclaw-workspace:/app/workspace mlclaw:local
```

浏览器访问 `http://服务器地址:3000`；在本机部署时访问 `http://127.0.0.1:3000`。

- `mlclaw-data` 保存数据库，`mlclaw-workspace` 保存工作区文件，重建容器时继续使用这两个卷。
- `TZ=Asia/Shanghai` 设置服务器时区，定时任务按该时区执行，可按需修改。
- 如需使用其他访问端口，把 `-p 3000:3000` 改成例如 `-p 8080:3000`。
- 镜像预装 Node.js、Python 3、pip 和 venv，应用默认以非 root 用户运行。

查看日志或停止服务：

```sh
docker logs --tail 100 -f mlclaw
docker stop -t 15 mlclaw
```

### 方式二：Node.js

要求 **Node.js 24 LTS、npm 11**。在项目根目录执行：

```sh
npm ci
npm run build
npm start
```

访问 `http://127.0.0.1:3000`，远程部署时将地址换成服务器地址。保持服务进程运行；需要停止时在终端按 `Ctrl+C`。

如果需要修改代码并实时预览：

```sh
npm run dev
```

开发模式访问 `http://127.0.0.1:5173`。不要同时启动开发后端和使用同一数据库的生产进程。

## 首次使用

### 1. 创建管理员

首次访问时设置管理员账号和密码，之后使用该账号登录。MlClaw 是单用户应用，不提供多人注册。需要修改密码时，进入“账号安全”。

### 2. 配置模型

1. 打开“模型服务”，点击“新增提供商”，选择预设或自定义服务。
2. 填写 API 基础地址与密钥。地址应包含服务所需的 API 前缀，例如 `https://api.example.com/v1`，**不要附加 `/chat/completions`**。
3. 点击“获取”选择模型，或手动填写模型 ID，然后保存提供商。
4. 选择全局默认模型，并点击“保存默认模型”。

可以使用“测试已保存配置”检查连接，测试会发起一次真实模型请求。非本机模型服务需使用 HTTPS；模型是否支持流式回复和工具调用，以实际服务为准。

### 3. 设置助手并开始对话

回到“对话”发送第一条消息，按引导设置助手身份和你的交流偏好。也可以在“助手设置”中手动填写名称、角色、用户资料和行为规则。完成首次身份设置后，助手才能开始使用文件、联网和脚本等工具。

输入框支持 `Enter` 发送、`Shift+Enter` 换行。发送按钮左侧可以临时切换模型；刷新或切换会话后恢复全局默认模型。打开“显示工具调用”可以查看执行过程，任务运行时可停止生成。

## 日常使用

### 搜索资料与阅读网页

进入“联网搜索”，选择服务并保存配置：Tavily、Firecrawl、Exa 和 Brave Search 使用对应 API Key；SearXNG 使用你信任的实例地址。启用后可尝试：

> 搜索这个主题的近期资料，整理主要观点，并附上来源链接。

Tavily、Firecrawl 和 Exa 可配置第三方正文提取，Brave Search 与 SearXNG 提供搜索结果。部分网页还可以直接读取；登录限制或反爬保护可能导致提取失败。定时任务需要联网时，另行开启“允许定时任务联网”。

### 整理文件与运行脚本

在“文件”页面上传资料，或让助手在工作区创建文件。例如：

> 读取工作区里的 notes.md，按主题整理，保存为 summary.md。

> 在工作区创建 scripts/report.mjs，统计当前目录下的 Markdown 文件数量，然后运行它。

工具路径相对于工作区，脚本也从工作区根目录运行。源码启动时工作区位于 `apps/server/workspace/`，Docker 中为 `/app/workspace/`。Node.js 脚本可以直接运行；源码部署执行 Python 等其他语言时，需自行准备解释器与依赖。

文件工具和网页上传当前限制单文件 64 KiB，共用 20 MiB、500 个文件的写入配额。覆盖和删除会直接生效，没有回收站。脚本使用应用账号的文件与网络权限，能够访问该账号有权访问的内容，并非独立沙箱，只应运行可信脚本。

### 维护记忆与安装技能

在“长期记忆”添加常用背景，例如“报告优先使用中文”“日期采用年月日格式”，并设置优先级。记忆需要手动添加和管理，不会自动把所有聊天内容存为长期记忆。

技能使用以下目录结构：

```text
workspace/
└── skills/
    └── my-skill/
        ├── SKILL.md
        └── scripts/
```

`SKILL.md` 使用包含 `name`、`description` 的 YAML 头部和 Markdown 操作说明。将技能文件夹放入工作区 `skills/` 后，在“技能管理”刷新查看。也可以让助手从可信 ZIP 链接下载并解压技能；系统不自动安装技能所需的依赖。

### 连接 QQ 和微信

进入“消息渠道”，完成配置后绑定本人身份：

| 渠道 | 配置步骤                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------ |
| QQ   | 填写机器人 AppID 和 AppSecret，保存后连接渠道，生成绑定码，再用本人 QQ 向机器人私聊发送完整的 `/bind 绑定码` |
| 微信 | 点击“微信扫码连接”，扫码并按提示确认；成功后生成绑定码，再用本人微信向机器人发送完整的 `/bind 绑定码`        |

QQ 需要机器人账号及相应平台权限，不能直接使用普通个人 QQ 登录。每个平台当前支持一个机器人账号、一个绑定身份和私聊文本，不支持群聊或图片、语音收发。在渠道中发送 `/stop` 可以停止该渠道当前任务。

### 连接 Telegram、Slack、Discord、钉钉和飞书

在“消息渠道”填写对应平台的配置，保存并连接，生成绑定码，再用本人账号向机器人私聊发送完整的 `/bind 绑定码`。绑定后支持私聊文本、`/stop` 取消和定时任务结果投递；每个平台一个账号、一个绑定身份，不接入群聊或多媒体。

| 渠道 | 需要填写与平台准备 |
| ---- | ------------------ |
| Telegram | 在 BotFather 创建机器人，填写 Bot Token 及其冒号前的数字 ID。使用 `getUpdates` 长轮询，不可同时运行其他轮询实例或配置 Telegram Webhook；应用不会替你删除已有 Webhook。 |
| Slack | 填写工作区 ID（`T...`）、同一已安装应用的 Bot Token（`xoxb`）和 App Token（`xapp`）。启用 Socket Mode，订阅 `message.im`；Bot 授权 `im:history`、`im:write`、`chat:write`，App Token 授权 `connections:write`，权限变更后重新安装应用。 |
| Discord | 在开发者平台创建机器人，填写机器人用户 ID 与 Bot Token，将应用安装到服务器后私聊机器人。接收 Direct Messages 事件，不需要读取服务器群消息；确认本人允许相关私信。 |
| 钉钉 | 创建企业内部应用机器人，填写 Client ID（AppKey / RobotCode）和 Client Secret。开启 Stream 模式并发布，授予机器人单聊消息发送权限，将本人加入应用可见范围。 |
| 飞书 | 创建企业自建应用，填写 App ID 和 App Secret，启用机器人和长连接，订阅 `im.message.receive_v1`，授予单聊消息读取与 `im:message:send_as_bot` 权限，发布版本并授权给本人。当前使用国内飞书端点。 |

凭据仅保存到服务端，网页不回显；同一应用留空保留，更换应用标识须重新填写全部凭据。上述五个平台每次保存都会停止连接并撤销本人绑定和旧定时投递授权，需要重新连接、绑定，并在计划中重新选择渠道。长轮询或长连接由服务器发起，无需额外公网回调地址；服务器须能访问对应平台。

### 连接 WeCom Bot

在企业微信群添加群机器人，复制 Webhook 地址，在“消息渠道 → WeCom Bot”填写一个英文/数字配置名称和完整地址，保存后启用。编辑定时任务，选择 WeCom Bot，即可把成功结果推送到该群。

仅接受 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` 地址，密钥不回显。此渠道不接收聊天、无需本人绑定；群内成员都能看到结果。文本按平台 UTF-8 字节限制截断，全文保留在网页；更换或重新保存配置后，需要在计划中重新选择渠道。

新六渠道已完成本地协议模拟与应用验证；真实账号权限、收发、平台限额和网络连通性仍需用实际账号联调。接口接受消息不代表最终送达或已读，失败或结果未知不会自动重发。

### 创建定时任务

在“定时任务”中新建计划：

1. 选择“AI 任务”或“脚本任务”，填写名称和任务内容。
2. 设置五段 Cron 表达式，预览后核对下一次执行时间。
3. 选择仅站内保存，或投递到已配置可用的渠道。
4. 保存并启用，可先“立即运行”一次，在执行记录中检查结果。

| 类型     | 示例                                  | 执行方式                                                     |
| -------- | ------------------------------------- | ------------------------------------------------------------ |
| AI 任务  | 每天读取工作区 notes.md，生成待办摘要 | 调用默认模型，只读文件或已授权联网资料，不写文件、不运行脚本 |
| 脚本任务 | `node scripts/report.mjs`             | 直接执行工作区脚本，不调用模型；可设置超时，每次使用最新脚本 |

常用 Cron 示例：

| 表达式        | 执行时间                            |
| ------------- | ----------------------------------- |
| `0 9 * * *`   | 每天 09:00                          |
| `0 9 * * 1-5` | 周一至周五 09:00                    |
| `0 */2 * * *` | 每天从 00:00 开始，每两小时执行一次 |

关闭网页不会停止调度，但服务器或应用必须保持运行；停机期间错过的触发不会补跑。执行时间以页面显示的服务器时区为准。

普通聊天也可以要求助手创建或修改计划，例如“每天九点读取 notes.md 生成摘要，发送到已绑定的微信”。创建后到“定时任务”确认内容、时间和投递渠道。

### 将结果推送到邮箱或 Webhook

在“消息渠道”填写 SMTP 主机、端口、加密方式、账号、密码或授权码，以及发件和本人收件邮箱，保存并启用；随后编辑定时计划，选择邮箱投递。

Webhook 支持配置地址、请求方式、Headers 和请求体模板，可用 `{{text}}` 插入任务结果、`{{id}}` 插入投递 ID，适合接入已有通知服务。

邮箱和 Webhook 当前用于**定时任务结果的出站推送**，不接收邮件聊天或外部消息。任务执行状态和投递状态分开展示，投递失败不会自动重跑任务。

## 数据与部署

| 内容   | Node.js 启动                     | Docker                                           |
| ------ | -------------------------------- | ------------------------------------------------ |
| 数据库 | `apps/server/data/mlclaw.sqlite` | `/app/data/mlclaw.sqlite`，存于 `mlclaw-data` 卷 |
| 工作区 | `apps/server/workspace/`         | `/app/workspace/`，存于 `mlclaw-workspace` 卷    |

数据库包含账号、模型与渠道配置、聊天记录等数据。迁移前先停止服务，再完整备份数据目录和工作区；不要将它们提交到公开仓库。一次只运行一个使用同一数据库的应用实例。

公网部署应配置 HTTPS 反向代理，保留原始 Host，并关闭 SSE 响应缓冲。首次初始化应由你本人完成后再开放访问。Docker 不需要挂载 Docker socket，也不需要 privileged 模式。仓库目前提供 Dockerfile，未提供 Compose 配置。

## 常见问题

| 问题                           | 检查方式                                                          |
| ------------------------------ | ----------------------------------------------------------------- |
| 无法开始对话                   | 确认已保存全局默认模型，并完成首次助手身份设置                    |
| 模型连接失败                   | 核对 API 前缀、密钥、模型 ID 和服务端网络；先测试已保存配置       |
| 助手无法联网                   | 在“联网搜索”启用并保存服务配置；定时任务还需单独允许联网          |
| QQ／微信已连接但不回复         | 检查本人绑定、平台权限及应用是否正在执行其他任务                  |
| 定时任务没有执行               | 检查是否启用、服务器时区、Cron 预览、服务是否在线，并查看执行记录 |
| 任务成功但没有收到推送         | 分别检查投递状态、渠道启用与绑定状态；平台接受不等于最终送达      |
| 页面提示已有实例或数据库被占用 | 检查是否重复启动，不要同时运行开发和生产后端                      |
| `npm start` 后没有页面         | 先执行 `npm run build`，确认构建成功后重新启动                    |

更多执行细节可在“运行记录”中查看；服务和渠道异常可在“系统日志”或服务终端日志中排查。当前全局同时只运行一个任务，忙碌时需等待或停止现有任务。
